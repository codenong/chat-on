# 04｜测试与验收

> 与设计稿第十节同构的执行清单。测试设备建议：一台真实 Android 手机（Android 10+，
> System WebView 已更新到最新）+ 一台桌面浏览器（阶段 0 核验用）。
> 测试 ZIP 按《01_分阶段路径规划》阶段 0 准备：脱敏样例覆盖多会话、分支、附件、
> 超长历史与异常消息。

## 一、测试用例

### 基本聊天

| # | 用例 | 预期 |
|---|---|---|
| C1 | 新建会话，发送消息 | 流式回复逐字出现，可停止 |
| C2 | 多轮对话、编辑提问、重新生成 | 分支切换正常，活动分支不被混线 |
| C3 | Markdown / 代码块 / 公式 / 图表 | 渲染正常 |
| C4 | 断网后发送 | 上游网络错误提示；草稿可保留后重试 |
| C5 | 横竖屏切换、软键盘弹出收起 | 输入框可见，不丢草稿，页面不重载丢状态 |

### 历史恢复

| # | 用例 | 预期 |
|---|---|---|
| H1 | 导入正常 ZIP | 上游确认框 → 导入成功提示“已导入 N 个对话”，会话列表出现旧对话 |
| H2 | 重复导入同一 ZIP | 结果一致（覆盖语义），不产生重复会话 |
| H3 | 损坏/非 DeepSeek ZIP | 上游提示无法识别（`backupUnrecognized`），现有会话不受影响 |
| H4 | 空ZIP / 0 字节 / 改名 txt | 明确失败提示，不崩溃 |
| H5 | 超大 ZIP（数百 MB） | 选择器→确认框正常；导入期间界面不冻结（仅上游页面自身进度），App 不被杀 |
| H6 | 选择器中取消 | toast“已取消导入”，无副作用 |
| H7 | 确认框点“如何备份” | 弹出备份说明对话框 |

### 分支与附件

| # | 用例 | 预期 |
|---|---|---|
| B1 | 含多分支历史的会话 | 打开后显示活动分支，BranchSwitcher 可切换 |
| B2 | 含图片附件的会话 | 图片在导入后可查看（原件随 ZIP 导入） |
| B3 | 含非图片附件或失效链接 | 上游给出缺失/不可用提示，不影响其他消息 |

### 持久化

| # | 用例 | 预期 |
|---|---|---|
| P1 | 强杀进程后重启 | 会话与设置仍在（IndexedDB 挂在可信 origin 下） |
| P2 | 重启手机后打开 | 数据仍在 |
| P3 | debug→release 同数据覆盖安装 | 数据仍在（同签名同 applicationId） |

### Key 与安全

| # | 用例 | 预期 |
|---|---|---|
| K1 | 无 Key 时打开 App | 引导页显示“未配置”，聊天发送时上游给出自身提示 |
| K2 | 错误 Key 验证 | “Key 无法验证…”（401/403 路径） |
| K3 | 无余额账户验证 | “DeepSeek API 账户余额不足…”（402 路径） |
| K4 | 断网验证 | “连接失败，请检查网络后重试。” |
| K5 | 替换 Key / 删除 Key | 新 Key 生效；删除后引导页回到“未配置”，发送消息被上游拦截 |
| K6 | `adb logcat` 全程抓取后 grep `sk-` | 无完整 Key 明文（`sk-[REDACTED]` 允许出现） |
| K7 | Chrome inspect 检查 localStorage | 无 `chat-demo:api-key` 明文条目 |
| K8 | 备份 ZIP 解包检查 | 无 API Key 字段 |
| K9 | 上游设置页保存新 Key | 原生侧同步保存（重启后仍有效），localStorage 不留明文 |

### 网络与计费

| # | 用例 | 预期 |
|---|---|---|
| N1 | 超长对话续聊 | 上游上下文策略生效；引导用户查看帮助页的费用说明 |

| N3 | 外链点击（帮助页官方地址） | 系统浏览器打开，WebView 内不跳转外域 |

### 可用性（对应阶段 4 小范围封闭测试）

| # | 用例 | 预期 |
|---|---|---|
| U1 | 非技术用户独立完成：导出→装 App→设 Key→导入→续聊 | 无需电脑、无需命令行、无需手工解压；记录卡点 |
| U2 | 询问“我的记录上传到哪里了？” | 用户能从文案/帮助页得到正确答案 |

## 二、MVP 发布判定（设计稿原文）

只有当用户能够在没有电脑、无需命令行、无需手工解压或编辑文件的情况下，完成：

**获取历史 ZIP → 设置 API Key → 导入 → 找到旧聊天 → 继续对话**

才认为第一版达到产品目标。对照用例：U1 全流程 + H1 + K2/K5 + C1。
