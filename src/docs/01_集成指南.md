## 二、重新 vendored（升级或首次）

前置条件：Node.js 22.12+、git、pnpm（corepack 可自动启用）。

```sh
scripts/fetch_chat_demo.sh          # 使用脚本内置的默认 commit
CHAT_DEMO_COMMIT=<sha> scripts/fetch_chat_demo.sh   # 指定 commit
```

脚本会：克隆 → checkout 指定 commit → `pnpm install --frozen-lockfile` → `pnpm run build`
→ 拷贝 `dist/` 到 `app/src/main/assets/chat/` → 写入 `COMMIT.txt`。

升级后**必须**完成第三节的三项契约核对，并跑 `docs/04_测试与验收.md` 的导入/导出回归。

## 三、升级必核对的适配契约（assets/inject/upstream-config.js）

壳层不修改上游源码，与上游的耦合点只有三个，全部集中在 `upstream-config.js`：

| 契约 | 当前值 | 核验方法（在上游源码中） |
|---|---|---|
| `localStorageKeys` | `['chat-demo:api-key']` | `src/services/settings.ts` 中 `KEYS.apiKey` |
| `importFileInputSelectors` | `input[type="file"][accept=".zip,application/zip,application/x-zip-compressed"]` | `src/components/settings/SettingsDialog.tsx` 中 `ImportHistory` 组件的隐藏 input |
| 导出触发方式 | 游离 `<a download>` + `link.click()`（由 `native-bridge.js` 的 `HTMLAnchorElement.prototype.click` 补丁接管） | 同文件 `ExportHistory` 组件 `onExport` |

### 为什么这样设计

- **Key（安全设计）**：上游把 API Key 明文存 localStorage。壳层用 document-start 注入的
  Storage 垫片拦截这三个读写：`getItem` 返回内存副本（值来自原生 Keystore 加密存储），
  `setItem`/`removeItem` 转发给原生保存/删除，并**删除**真实 localStorage 条目。
  因此 Key 只存在于页面内存 + 原生密文存储，`localStorage` 中没有明文 Key。
  启动 Key 由原生以 JSON 转义嵌入 document-start 脚本，保证上游首次同步读取即可命中。
- **导入（扫描勾选 → 过滤重建 → 追加）**：原生先复制 SAF 选中的 ZIP 到 cacheDir，
  只读 manifest 与会话索引完成校验解析（`ArchiveScanner`），弹出会话勾选对话框；
  非全选时由 `FilteredArchiveBuilder` 按官方条目顺序重建「只含所选会话」的导出包，
  再把（重建后的）ZIP 挂到 `https://appassets.androidplatform.net/__import_local__/current.zip`
  （`ImportStreamPathHandler` 经 ContentResolver 流式返回）。页面收到 `appendImport`
  后直接调用官方解析器（importArchive → IndexedDB 暂存区）与官方常规写库函数
  （E1 按会话 upsert），跳过官方「清空现网库再搬入」的提交步骤（Xz）——实现
  **追加导入**：现有对话保留，同 id 会话按导入侧覆盖。官方模块指纹失效
  （MODULE_NOT_FOUND）时回退旧链路：`deliverImport` 把文件赋给上游隐藏 file input，
  走官方覆盖式导入 UI。全程没有 Base64 桥接，大 ZIP 不占壳层内存。
- **导出（WebView 限制的补齐）**：WebView 无法把 blob: 下载落盘。注入脚本拦截
  导出锚点的 `click`，`fetch` blob 后按 256 KB 分块 base64 发回原生，
  `BackupManager` 先写缓存临时文件，用户选择保存位置后一次性拷贝。

## 四、桥接协议速查

页面 → 原生（JSON 字符串，`assistantNativeBridge.postMessage`）：
`getKey` / `saveKey{key}` / `deleteKey` / `pickImport` / `importResult{ok,code,count}` /
`exportStart{id,name,size}` / `exportChunk{id,index,data}` / `exportEnd{id}` / `exportError{id,reason}`。

原生 → 页面（`assistantNativeBridge.onmessage`）：
`keyValue{value}`（空串=已删除）/ `deliverImport{url,name}`（旧链路兜底）/
`appendImport{url,name}`（追加导入，0.2.0 起）。

原生侧入口：`bridge/AssistantBridgeListener.kt`（仅可信 origin、仅主框架）。
注入侧入口：`assets/inject/native-bridge.js`。

## 五、构建与运行

1. Android Studio（Ladybug+）或命令行 JDK 17 打开项目；
2. `./gradlew :app:assembleDebug` 生成 `app/build/outputs/apk/debug/app-debug.apk`；
3. WebView 要求：设备 System WebView 支持同源 WebMessageListener 与
   `addDocumentStartJavaScript`（近年 Play 通道自动更新的 WebView 均满足）；
   设备过旧时，`MainActivity` 桥接初始化失败会记入日志，聊天仍可运行但密钥安全与
   导入投递不可用——此时不应发布。

## 六、常见集成问题排查

| 现象 | 可能原因与处理 |
|---|---|
| 导入 toast “未找到官方导入入口” | 上游 DOM 变化：更新 `importFileInputSelectors`；先在 Chrome 里 `document.querySelector(...)` 验证 |
| 设置页保存 Key 后重启又要求输入 | 契约 `localStorageKeys` 与上游 `KEYS.apiKey` 不一致；垫片没拦住真实键名 |
| Key 验证通过但发送消息 401 | `getItem` 垫片未生效（检查 `__DS_ASSISTANT_BRIDGE__` 是否注入、origin 是否为可信 origin） |
| 导出点击后无反应 | 上游改用了非 `<a download>` 的下载方式；按第三节重新核验导出触发方式 |
| 打开 App 白屏 | `assets/chat/index.html` 缺失（未 vendored）；运行 `scripts/fetch_chat_demo.sh` |
| 主框架错误页 | 检查 `assets/chat/` 完整性（`static/js/`、`static/css/` 是否齐全） |

## 七、升级上游 commit 的回归清单（最低限度）

1. 桌面浏览器按上游 README 验证新版本导入/导出/续聊正常；
2. 重新 vendored 后跑 `docs/04_测试与验收.md` 中“历史恢复”“分支”“Key”三组用例；
3. `git diff` 检查 `upstream-config.js` 是否需要更新；
4. 在 `docs/04_测试与验收.md` 底部登记新 commit 与回归日期。
