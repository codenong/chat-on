## 二、设计稿条款 → 实现位置对照

### 4.1 首次启动

| 条款 | 实现位置 |
|---|---|
| 一句话说明 | `res/values/strings.xml` `onboarding_tagline`；`res/layout/view_onboarding.xml` |
| 检查 Key 是否配置、显示状态 | `ui/OnboardingController.kt`（`refreshKeyStatus`，显示掩码 `sk-…abcd`） |
| 未配置时显示“设置 API Key”入口 | 引导页主按钮 → `ui/KeySetupDialog.kt` |
| 三个帮助入口 | 引导页 → `HelpPage` 枚举 → `assets/help/` 四个页面 |
| 允许先导入后配置 Key | 引导页导入按钮不依赖 Key；发送消息时由上游页面自身校验 Key |

### 4.2 主聊天界面

| 条款 | 实现位置 |
|---|---|
| 保留官方布局/颜色/交互，不重写 UI | 完整 vendored 官方 dist，`MainActivity` 不注入任何样式改动 |
| 不增加首页信息流 / banner / 会员 / 广告 | 壳层仅一条工具条（承载系统级能力菜单），见 `activity_main.xml` 注释 |
| Android 外壳只补充系统级能力 | `MainActivity` 仅编排：菜单、返回键、下载接管、帮助页 |

> 说明：为提供“设置 Key / 导入 / 备份 / 帮助”的系统级入口，壳层在页面顶部保留了一条
> 无复杂导航的工具条（仅溢出菜单）。若接受“仅靠引导页 + 上游设置页进入”的方案，可删除
> `toolbar`，这是有意的最小偏离，发布前可按可用性测试结果取舍。

### 4.3 导入入口

| 条款 | 实现位置 |
|---|---|
| 只引导选择官方导出 ZIP，不要求解压/编辑 | `fileimport/FilePicker.kt`（SAF，ZIP MIME 白名单） |
| 选择后显示文件名，开始前校验 | `fileimport/ImportController.kt`（读取文件名/大小并展示）；格式校验交给上游 `checkArchiveFormat` |
| 导入前覆盖提示 + 备份选项 | `strings.xml` `import_confirm_message`（按 4.3 原文）；对话框含“如何备份”按钮 |
| 导入中提示保持 App 打开 | `strings.xml` `import_delivered` / `import_large_file_note` |
| 不让用户误以为上传到开发者服务器 | 提示文案明确“交给官方导入器处理”；隐私页说明数据去向 |
| 导入完成显示结果 | 上游导入器自带结果提示（“已导入 N 个对话”）；壳层 toast 汇报投递结果 |
| 支持取消 | 选择器阶段可取消（有“已取消导入”提示）；官方确认框可取消；导入开始后以上游能力为准 |

### 五、关键用户流程

| 流程 | 实现位置 |

### 6.2 数据存储

| 条款 | 实现 |
|---|---|
| 会话与附件沿用 IndexedDB | 上游原样保留，origin 固定为 `appassets.androidplatform.net` |
| 敏感 Key 迁出明文 localStorage | `native-bridge.js` Storage 垫片：`getItem` 返回内存副本，`setItem`/`removeItem` 转发原生 |
| Key 由 Keystore 保护、按需提供 | `SecureKeyStore` + `AssistantBridgeListener.sendKey`（仅可信 origin 主框架可请求） |
| 备份不含 API Key | 上游导出本就不含 Key；`backup_rules.xml` / `data_extraction_rules.xml` 再排除密文存储文件 |
| 不引入 Room/SQLite 第二套数据库 | 未引入；壳层没有任何会话数据库 |

### 6.3 API 请求与模型上下文

| 条款 | 实现 |
|---|---|
| 沿用上游 API 协议与默认模型 | 未改动上游 `__API_ORIGIN__`（默认 `https://api.deepseek.com`）与默认模型 |
| 不写死模型名/价格 | 壳层不含任何模型名或价格；帮助页只链接官方价格页 |
| 上下文策略沿用上游 | 未改动；导入≠全量发送的说明写在帮助页与隐私页 |

### 6.4 ZIP 导入格式注意事项

全部通过**复用官方导入器**满足（不自行解析）：分支树/活动分支、`inserted_at` 非单调、
reasoning 与网页阅读交错、模板回复与失败状态过滤、数百 MB 附件解析，均由上游
`importArchive.ts` 在锁定 commit 下保证；壳层只负责把原始字节流交给它。

### 七、API Key 安全与信任边界

| 条款 | 实现 |
|---|---|
| 1 不向开发者服务器上传 Key | 全链路无自有服务器；`docs/03_隐私说明草稿.md` 声明 |
| 2 只加载 APK 内可信资源 | `WebViewAssetLoader` + 关闭 file/content 访问 |
| 3 非白名单导航交给系统浏览器 | `WebViewConfig.createClient` |
| 4 origin-scoped WebMessageListener | `WebViewCompat.addWebMessageListener`，允许列表仅可信 origin |
| 5 不用宽泛 addJavascriptInterface | 未使用；桥接对象仅注入可信 origin 且仅主框架（原生侧二次校验） |
| 6 Key 输入默认隐藏 | `view_key_setup.xml` `textPassword` + 显隐切换 |
| 7 替换/删除 Key | `KeySetupDialog`（重新粘贴即替换；删除按钮） |
| 8 日志/埋点/崩溃无 Key、正文、附件 | 无任何埋点 SDK；`util/LogRedactor`；异常只记类名；附单元测试 `LogRedactorTest` |
| 9 不通过客服/截图收集 Key | 帮助页与隐私页明确提示 |

### 八、异常状态与用户文案

`res/values/strings.xml` 按“场景 → 文案”组织，文案与设计稿第八节一致：
未配置 Key（引导页 + 上游提示）、Key 无效、余额不足、网络错误、ZIP 不支持
（上游 `backupUnrecognized` 原生提示）、导入覆盖提示、上下文过长（帮助页说明）。
